# Integration contract for the native ending candidate

The candidate remains in `prototype/ScoreSharedEndingDetector.swift`; it has not changed production Core or the app.

1. Finish staff detection and resolve the complete system roster before calling `analyze(in:page:profile:observedFailure:isCancelled:)`. The detector verifies one-to-one staff ownership with the planner and ignores prior shared-mark metadata for that verification. Use the same local source display raster and saved deskew geometry as the inventory. The evaluated native raster limit is 2400 × 3500 pixels.
2. Collect every selected page's `PageResult`, including verified zero-staff pages and unresolved pages, and call `pairs(in:isCancelled:)` after all page analyses finish. A missing page index or unresolved page is an adjacency barrier; a supplied verified blank page does not invent a system. A score-level pass is required because a first/second pair may cross a system or page boundary.
3. Treat OCR evidence as recognition evidence only. Retain literal strings, including ambiguous fast `I`, and never engrave a replacement digit. Each accepted candidate carries source copy bounds in top-down PDF points. Normalize them by that page's physical dimensions for source-copy metadata. Combine the two bounds only when both endings belong to the same verified system and anchor. Otherwise retain one copy on each respective system. The reviewed Brahms export uses five source rectangles for eight ending brackets.
4. Preserve previously recognized headings, navigation sentences, and destination symbols. The candidate export stages ending rectangles as empty-text, above-system `ScoreSharedNavigation` values for compatibility, but this is not sufficient production provenance: rerunning the current destination CLI removes its own empty-text glyph values. Add distinct ending provenance or reconstruct all categories atomically before enabling this in a resumable workflow.
5. A Vision runtime error yields an unverified `PageResult` and calls `observedFailure`; the batch harness aborts without writing a success result. Cancellation returns no partial accepted pair. Keep those outcomes distinct from zero endings.
6. Retain source-copy fidelity and the independent safety-envelope failures. This detector does not remove neighboring musical fragments, prove every repeat semantic, or support unpaired/third endings and unusual number lists.

The final full68-page recognition run has the same results after the independent adjacency/cancellation fixes. Both source IDs are hash-bound in `review.json`; no source page ID is used in the recognition logic. Every selected Brahms ending lies on an unrectified source page, so its coordinates also directly correspond to the original PDF.

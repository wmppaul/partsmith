# Recipient-local ending integration

The app coordinator now performs a separate local-recipient phase only on physical pages and systems belonging to already accepted global ending pairs. It keeps the complete selected-page roster and existing barriers for global pairing. Local evidence stays keyed by recipient and cannot create or repair a global pair. Progress counts the paired physical pages; cancellation before, during or after local OCR returns the original analyses, without partial metadata. Optional local failures keep the shared copies.

The native local detector, model and planner retain the reviewed scratch geometry. Both local brackets must match the global source-page/system positions and horizontal endpoints, belong above the recipient's first staff, and fit completely within its current main crops. The first-staff helper checks empty/nonfinite/unordered arrays before indexing. The planner verifies both exact page-local global members before suppressing a copy, including same-page pairs spanning two systems.

Explicit `automaticLocalEndingPairIDs` preserve a crop editor's automatic choice when the UI materializes an override. A narrowed crop restores necessary shared copies; an explicit Remove Copy clears that pair marker. Invalidation also removes a restored automatic copy that was later materialized by an unrelated edit, even if the recipient's staff IDs or kind changed. On linked partner pages, ending-only cleanup preserves coincident heading/navigation/destination-owned rectangles. The changed page still invalidates its automatic categories independently.

The five-file scratch candidate was extended with coordinator wiring, Xcode registration, compiler-list dependencies and self-contained permanent controls in `tools/test_local_ending_counterparts.swift`, invoked by `tools/test_shared_ending_app.sh`. No scratch inventory, source PDF or OCR cache is needed for the default controls. The optional `--corpus` mode additionally replays the existing hash-bound 68-page evidence. Optional new model and override fields preserve legacy decoding; populated evidence and automatic markers round-trip.

Independent review found and reproduced three gaps in the first scratch candidate: either same-page system entry could accidentally certify both global members; a restored copy materialized by an unrelated edit could survive reassignment; linked ending-only cleanup could remove an overlapping other-category copy. These are fixed and represented in permanent regressions, with an additional staff-ID-swap control. Initial failed evidence remains in the independent scratch review; the prior candidate report is not rewritten to hide those findings.

The earlier native recipient scan/source review and all-five-part Schumann export are recorded in `../ending-local-counterparts/`: four complete Piano-owned pairs, five duplicate rows removed, all 825 main crops unchanged, 74 rendered pages matching their expected controls. That export validates the local recognition/retention behavior, but predates coordinator wiring and the invalidation fixes; fresh real workflow and universal-app checks are root-owned follow-up validation. Global numeral-window and Schumann tempo experiments were not promoted by this change.

Run `bash tools/test_shared_ending_app.sh` for self-contained controls, or append `--corpus` for the existing frozen positive-score replay. Final run passed 62 self-contained local controls, 65 integration/frozen-corpus checks, and 35 worker/cancellation checks. `permanent-controls.log` and `verification.json` bind the final binary, code and results. The Xcode project passes property-list validation and the diff has no whitespace errors.

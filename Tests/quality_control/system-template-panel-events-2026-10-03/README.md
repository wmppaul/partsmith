# Native panel event check

The actual production `ScoreSystemTemplatePanel` completed Find Similar Systems → Show → Use Selected Layouts in its own offscreen AppKit window. Local mouse events, delivered directly to that test window, selected the real controls. The panel found 46 Erlkönig proposals; its default selection accepted the 43 full-roster systems, leaving the three Piano-only systems unchecked because their missing Voice needs target bar counts. The callback log records **43 applied and 1 revealed**. No user application, score document, or app copy was opened or changed.

The test runs the exact final panel and Core files recorded in `source-hashes.json`, compiled without optimization. Its initial review uses the same complete Erlkönig inventory, profile and two seeds as the matcher evaluation. Screenshots show a 330-point-wide panel before matching, while working, with results, and after the apply callback. They were inspected. The offscreen view-cache capture fails to paint the footer button below the nested scroll view in the results screenshot, although the button receives its local click at (100, 541) and performs the verified apply. Consequently this is an executed interaction check plus partial visual inspection, **not certification of the complete rendered app window or footer appearance**. The source-score highlighting callback was invoked once; actual source scrolling is tested separately in the independent scroll report.

Accessibility traversal was unavailable in this offscreen host, so the successful harness uses local mouse events. Earlier accessibility-only attempts were not counted as successful interactions. The harness neither posts global mouse events nor activates the user's running Partsmith app. All final Core and panel bytes match production. The optimized release is built separately; this debug-mode run is not a performance measurement.

To reproduce, compile `panel-events.swift` and the recorded Core/panel files with AppKit/PDFKit/SwiftUI, then pass the matcher evaluation folder, a fresh output folder and the original Erlkönig source PDF. The harness watches its output `commands` directory for JSON commands containing a local `click: [x, y]`, a `snapshot` filename, or `finish: true`. The saved commands document the actual sequence; submit them individually after the preceding visible state is ready, rather than preloading them before the asynchronous matcher finishes. The source, inventory and seeds are bound by the companion matcher/workflow reports. Native musical coverage, source copies and generated rests are assessed by the separate complete workflow; this panel test does not certify crop quality.

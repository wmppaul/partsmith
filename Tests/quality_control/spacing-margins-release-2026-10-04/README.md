# Spacing, margins and applied-scale feedback

The preferred system gap now supports 4–200 points in the Inspector, the document setter and new-part inheritance. New projects use 18-point side margins with the existing 48-point top/bottom margins. Existing projects retain their saved margins and per-part overrides. The Inspector shows the applied scale prominently when the requested scale reaches the page-width limit, and explains that balancing can reduce preferred spacing. Turn off Balance Page Fill to retain the full gap.

The safe width limit and balancing algorithm remain intact. Reducing side margins enlarges physical notation by increasing usable page width; it does not change the scale multiplier's limit relative to fitting the original crop. This is why requests such as 1.30× and 1.40× can remain identical at a 1.14× limit. No source notation is clipped to force a higher scale.

The independent [layout/export review](../layout-controls-2026-10-04/README.md) passes 5,443 layout assertions and 302 native export checks. Coverage includes measured 200-point gaps, balancing, Undo/Redo, saved values, new-part inheritance, historical 48-point layouts, new 18-point layout geometry and complete-source pixel references for scanned and digital exports. Root visually compared the scanned fixture at 48-point and 18-point margins. The separate [Inspector review](../inspector-spacing-ui-2026-10-04/README.md) verifies the controls and text in a narrow native view. Its scale metadata is supplied as a UI fixture; actual scale calculation is covered by the layout/export tests.

# System-template batch and panel: independent review

The final batch fix passes **23/23 independent API checks**. A real ordering failure was reproduced before the fix: disjoint physical groups with swapped system indices returned a review whose plan had `canApply=true`. The new guard rejects that assignment before returning the review, while accepting a correctly ordered choice list presented in reverse array order and valid geometry whose numeric staff IDs are not monotonic. No remaining blocking batch/panel issue was found within this review's scope.

The original 21-control run passed 20 checks. Its failing result is retained verbatim: system 0 used physical IDs `[0]`/`[1,2]`, system 1 used lower IDs `[5]`/`[6,7]`, then system 2 used the physically higher generated-rest anchor/IDs `[3,4]`; `canApply=true`. This proves inconsistent system identity was accepted, not that a particular exported PDF was reordered or lost notes—no counterexample export was made. The fixed run retains every original control and adds ordering against an existing lower-page template, plus acceptance when numeric staff IDs do not follow vertical position.

Independent controls cover cancellation at all six checkpoints in the two-choice fixture, including cancellation after replanning; unchanged input after cancellation; a valid staged first choice followed by an invalid second assignment; duplicate analysis pages/override pages; nonfinite page dimensions; stale reuse; preservation of an existing explicit crop/source copy; and physical ordering across existing plus new systems. These are actual calls to `ScoreSystemAssignmentBatch.applying`, not a reimplementation. They verify atomic returned-value semantics. The parent's separate 27-check suite and native score studies are outside this report.

Read-only UI review found and verified two additional fixes by the parent:

- While an apply worker was running, changing selection or rest counts could previously be ignored because the worker had already captured its choices. The final panel disables Select Matches/Clear and the entire results list during `isApplying`, including fields, toggles and Show; Stop remains available.
- Setup-wide diagnostics use page index -1. They are now displayed as plain matching details, instead of “Page 0” or an unmatched-page count containing the sentinel.

The final panel compares profile, source bytes, rectifications, analyses, overrides, selected pages and exclusions both before applying and after the worker returns. Per-run IDs prevent stopped, superseded or disappeared workers from publishing. The worker owns a private PDF document, does not fall back to raw coordinates when corrected rendering fails, and the matcher requires exact analysis-image dimensions. Suggestion bounds are finite normalized values built from validated staff positions. These are source-code review conclusions; this agent did **not** run computer-use UI tests, benchmark cancellation latency, or certify the matcher's instrument/clef accuracy. A replan already in progress may finish on the background worker after Stop, but its cancelled result is not published.

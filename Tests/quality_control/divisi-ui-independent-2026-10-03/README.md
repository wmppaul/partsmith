# Per-system staff counts: independent UI/state review

The five frozen source files in `.build/divisi-assignment-release-2026-10-03` were reviewed without production changes. No blocking integration finding was identified. The assignment controls bind local counts separately from the global profile; Load reconstructs the actual saved musical staff groups, Show transfers a matched layout's counts, and both single and batch actions pass those counts to the native assignment API. The panel displays each proposed grouping. Competing groupings remain separate explicit choices.

Eighteen focused state controls pass against the frozen source. Ten actual UI declarations/expressions were extracted verbatim except for removing private access. The harness executes those bodies with native Core values; it does not reimplement their assignment logic. It covers default counts, 2+1 divisi, loading saved groups, Show then Assign, retained layout choices with cleared duration, cached counts for unchecked parts, counted absence and Load, batch forwarding, immutable global profile, and stale-result/duration gates. Original source hashes and extracted-body hashes are retained. A first harness compile used a nonexistent mutable Suggestion.id argument; the fixture initialization was corrected before any execution. No source behavior or expected result changed.

Static review covers the visual count binding (1–4, disabled for unchecked parts), same-page and deferred cross-page Show, async result identity/cancellation, and reset on a new Auto result. This is not an interactive SwiftUI click, screenshot, accessibility or system-recognition test. The separate Core adversarial suite is owned by the other reviewer and is not counted here. Physical system/part ownership still comes from reviewed source assignments; no missing bar count is inferred or copied.

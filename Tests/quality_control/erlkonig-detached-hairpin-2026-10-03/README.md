# Detached final-staff hairpin experiment — not promoted

This private native-analysis candidate recovers the complete omitted diminuendo in Schubert’s *Erlkönig*, source page 4, system 4, Piano. It is **not ready for automatic use**: eight of eighteen synthetic positive envelopes remain incomplete, and a footer ornament with the same pixels as a hairpin is indistinguishable by this rule. Production code, the frozen app release, and existing part deliveries were not changed by this experiment. The parent’s separately reviewed manual output is not a candidate export.

The original PDF was inspected before coding. Its two round-capped lines meet at an apex and occupy x 390.079–466.698, y 808.503–814.961 pt including stroke width. Native ordinary component 407 already finds the symbol (x 389.908–466.633, y 808.492–815.106 pt), but does not assign it to a staff. Its top is 0.661 pt below the final crop-discovery seed, and the nearby assigned note component is approximately 3.64 staff spaces away—outside the existing detached-ink relay. The current Piano crop ends at y 798.861 pt, so the entire dynamic is omitted. The source-defined obligation and original vector paths are retained; no source guard was weakened.

The frozen rule examines only unowned components below the final physical staff, near that staff. It requires two thin, nearly straight source-pixel strokes that converge, with bounded width, height, separation, residuals and thickness. Accepted components are appended as typed ownership alternatives for the final staff; every ordinary component remains unchanged. The existing planner may expand that staff’s crop outward. This does not modify general crop padding, change another staff’s ownership, or propagate through a chain of components. Exact numeric gates were recorded in `rule-before-results.json` before the first candidate run and were not retuned after misses or adversarial failures.

The full-width original final system and both Piano strips were directly viewed. The expanded strip contains both hairpin strokes, their complete apex, and the existing notes/rests; no neighboring staff is imported on this real page. Every other Erlkönig crop and all matched Brahms plans are unchanged. This is a source-strip review, **not a fresh document Auto run, candidate PDF export, pagination review, or whole-score musical certification**. Native replay uses frozen staff candidates and current source-bound direction metadata; Brahms uses the five existing corrected analysis rasters bound in the archive. The original source hash is `dfd76c0ddb804d0587048c61e4edec8dcd7a75b6e39e27420087ed510d89046b`.

The added footer lookalike has deliberately identical geometry and position to a positive dynamic. Three of its nine raster variants are classified and two newly widen the crop (the third was already inside the baseline crop). This is an observed semantic false positive, not a hypothetical disclaimer. The other negatives do not establish general text/footer safety. Above-staff and between-staff dynamics are outside scope; resolution and scan fragmentation still produce conservative positive misses. A useful next mechanism would need independent ownership/context evidence, rather than tuning these thresholds against this one page.

`reproduction-evidence.zip` contains both frozen 23-file Core snapshots, the one-file patch, protocols, harnesses, source/profile/override inventories, full native plans, rasters, synthetic results and logs, with per-member hashes. Executable binaries and original PDFs are excluded. Restore the archive under `.build/erlkonig-hairpin-2026-10-03` in this repository and use `run.sh`, `run-brahms.sh`, `run-controls.sh`, `run-footer-controls.sh` and `run-existing-current.sh`; they compile against the private candidate snapshot. The current permanent test source was copied before execution, while the older 765-check run is retained as historical evidence. An initial harness failure required a missing `rectifications` JSON field; it was fixed before any successful native result and is preserved in the initial logs.

# Direct crop editing in Preview

The actual PDFPreviewContainerView passes 34 native AppKit interaction checks in a hidden, isolated window. The test uses the unchanged Brahms242312 source and deliberately oversized sample crops to exercise the handles. These are UI fixtures, not proposed extracted parts. Root inspected `drag-preview.png`: top/bottom handles align with the rendered strip; pending removed ink is visibly shaded. The controls are view overlays and never enter the exported PDF.

Checks cover selecting the original band, no document writes during 20 drag events, exactly one commit on release, top/bottom direction and actual PDFView scaling, Escape, disabling stale snapshots, cancelling a draft when PDFKit itself scrolls or zooms, forwarding wheel events to the internal scroll view, preserving manual zoom and keeping the selected system at its screen position across reflow. The original app and user documents were not opened or modified. Native graphics access was needed; sandbox-only runs failed at IOSurface setup before completing the UI checks. The final native run passes.

The separate Core suite passes 110 geometry/publication/document checks, including Undo/Redo, clipping whiteouts to resized crops, saving/reopening and native export. Existing 5,389 layout and 169 export checks also pass; see the sibling preview-crop-core report. An unchanged full-part preview regression passes 24 checks on the 131-band Brahms Trio Clarinet part, producing 10 pages with 0.23 ms enqueue time and identical preview/export pixels on the checked first/middle/final pages. These timings describe enqueueing, not total rendering duration.

The feature shares the ordinary source band; selecting a preview strip also selects its source page without leaving Preview. Cropping is disabled for generated and compressed rests. The user must restore a compressed rest to its original crop before resizing. The feature does not change staff detection or establish automatic musical ownership. A trim can remove intended notation, so the preview shows the user's pending cut and supports Undo; no mandatory acknowledgement is added.

This report verifies isolated native component interaction and export/model integration, not a walkthrough of the user's running app. Source bindings and original test logs are preserved. The release is built separately from a frozen source copy.

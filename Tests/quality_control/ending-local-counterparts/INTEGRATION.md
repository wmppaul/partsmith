# Integration proposal — not promoted

The reviewed patch applies to the five hash-bound baseline files in `patch-files.json`. Apply the diff, not the full Core snapshot. `ScoreSharedEndingDetector` only factors the existing analysis body into an internal overload accepting verified staff anchors; preserve any separately reviewed global OCR fallback changes when merging that hunk.

1. Add `ScoreLocalEndingPreservation.swift` to Xcode and explicit compiler lists. `ScoreSharedEnding.localCounterparts` is optional, so old inventories remain readable. The counterpart's `globalMembers` binds exact source coordinates, page/system ownership, roles and evidence; its local members never change `pairID` or the global pairing stream.
2. In `ScoreSharedDirectionWorkflow`, after the existing all-selected-page global pairing and metadata factory complete, run a separate optional local-recipient pass. Do not filter or rebuild the global pairing roster. Only source pages and systems belonging to already accepted global pairs need local recognition. Reuse the same source/rectified-display renderer; an uncorrected fallback would be invalid. Keep unknown, failed, sparse and unresolved global-page barriers unchanged.
3. Build the ordinary current plan for eligible fixed-layout music pages, retaining the current global metadata. For each recipient part in an accepted pair's source system, except the source owner, call `ScoreLocalEndingPreservation.analyze(in:page:profile:plan:partID:systems:observedFailure:isCancelled:)`. This verifies the page's physical staff partition and anchors the existing OCR/geometry primitive over the recipient's first staff. Keep results keyed by recipient part, then source page. Do not pass them to `ScoreSharedEndingDetector.pairs`.
4. For each accepted global pair and recipient, call `counterpart(global:partID:localPages:pages:plan:)`. Only a unique complete local pair at both matching horizontal bracket endpoints can return evidence. Both padded source boxes must already be retained. Attach that counterpart to every page-local `ScoreSharedEnding` whose `members` equal `counterpart.globalMembers`. Stage this atomically and return the original analyses on cancellation. A local failure should keep the global copy and add optional information; it must not clear headings/navigation/destinations/global endings or create an acceptance gate.
5. The patched planner revalidates both global and local member ownership and complete crop containment on every plan, including initially supplied overrides. The separate final filter removes only the exact ending source rectangle for its recipient. UI-generated crop overrides retain `automaticLocalEndingPairIDs`; explicit Remove Copy clears the pair marker. Do not strip this field when serializing overrides. No new user interaction is required.

Before promotion, add an injectable local-recognition service to the direction coordinator and test failure/cancellation between the global and local stages, the complete sparse-page roster, and cross-page metadata staging. The existing scratch controls cover factory/planner/review behavior, not that new coordinator glue. Run the real native workflow on the five positive full-score inputs after wiring, with saved source corrections and hash-bound sources. Review any newly discovered local counterparts rather than assuming the existing 68-page metadata-free replay proves their correctness. Re-run final source-copy and output-placement comparisons, and inspect the five corrected Piano rows in the app.

The candidate is deliberately independent of the root agent's global numeral-width experiment. Do not use global OCR recall improvements as evidence that recipient ownership, retained local pixels or suppression are correct; validate combined output separately.

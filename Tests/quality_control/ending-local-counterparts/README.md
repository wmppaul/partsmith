# Recipient-local ending preservation — scratch candidate

The isolated candidate independently finds both printed ending brackets above a recipient's own first staff. It suppresses a global source copy only when both local members match the same source pages, systems and horizontal bracket endpoints, and both complete padded local bounds already fit the recipient's unchanged main crops. Numeral equality, another pair on the same page, or a neighboring instrument's ending is insufficient. Local candidates never enter global score pairing.

The real native test used the six affected physical pages of Brahms 242312, Schumann 06822 and Brahms 09200 from the frozen broader scan. It found four complete Piano-owned Schumann pairs, removing exactly five duplicate rows: p6 systems 1/2, p16 system 3, p18 system 2, and p20 system 3. Neither Brahms variant produced a recipient counterpart. Across the three scores, copies change from 26 to 21; every main crop, staff identity and other band field remains unchanged. There were no local OCR/render errors. All eight local members were inspected against the original source with the complete padded boxes and original main-crop edges shown in `source-review/`.

All five Schumann parts were exported through the current native exporter compiled against the final scratch Core: 74 pages, versus 75 with the duplicated piano copies. The four string parts remain 12 pages each; every one of their 48 rendered pages and every placement is identical to the preceding with-ending output. Piano returns from 27 to 26 pages; every one of its 26 rendered pages and every placement is identical to the same-Core no-ending control, which already contains these locally printed endings. All 825 source crops are unchanged. All five corrected Piano rows were visually inspected after source review; the duplicated copies are gone and complete local numerals/lines/hooks remain. Source-copy coordinates and original pixels are never edited or replaced.

The final scratch tests pass 41 targeted controls plus 825 main-band equality assertions. They cover wrong part/staff/page/system/role, horizontal start/end mismatch, incomplete or ambiguous local recognition, missing/unverified pages, crop clipping, initial reassignment, cancellation, category collisions, serialization, and two-page invalidation. The actual `ScoreDetectionReview` path proves that a crop edit clipping a local bracket restores both required automatic copies, while an explicit Remove Copy survives replanning and repeated crop edits. Empty, nonfinite and unordered first-staff line arrays are rejected before indexing. The existing 65 ending integration and 27 worker/cancellation checks also pass, including exact frozen 68-page / 1,009-band / 52-copy replay without local counterpart metadata.

The crop-edit case required explicit provenance: `automaticLocalEndingPairIDs` distinguishes an automatic choice materialized into a UI crop override from an initially supplied manual source-marking list. Only those specific ending pairs may regenerate; Remove Copy clears the affected pair marker. Other directions, manual rectangles, empty removal lists and original source crops remain authoritative.

The isolated runner drives recognition/factory calls, and the existing native exporter exercises application, layout, PDF output and embedded-project creation. **The recognition call is not yet wired into the app's direction coordinator.** See `INTEGRATION.md` for that remaining step and review requirements.
